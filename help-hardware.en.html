Supported boards

The site includes MicroPython v1.29.0 firmware for the ESP32, ESP32-S2, S3 and C3, and picks the right one by detecting the chip during installation. The chip inside ESP32-S and ESP-WROOM-32 modules is an ESP32, which is different from the ESP32-S2 and S3. The flash must be at least 4 MB. With any other chip or too little flash, the site stops before erasing anything.

How the ESP32 chips differ

Boards sold as ESP32 can carry several different chips. For classes, the classic ESP32 is the best choice, because it has the most teaching material and online help. The other chips number their pins differently, so see the pin table under "Wiring notes".

  • S3 model names: N16R8, for example, means 16 MB of flash and 8 MB of octal PSRAM. Octal PSRAM uses GPIO 35–37, so do not connect parts to those pins. If the board has two USB-C ports, try the one marked COM or UART first.
  • Boards with CAM in the name: this site's firmware has no camera support, so they work only as plain boards.
  • C3, S2 and S3 boards: some have no USB-to-serial chip and use the chip's own USB instead, so no driver is needed.

Can I use an Arduino UNO?

No. This site only has MicroPython firmware for the ESP32 family, and the classic UNO R3 has too little memory to run MicroPython. ESP32 Lab also has an Arduino edition, but "Arduino" there means the Arduino framework you write code with (setup(), digitalWrite() and so on), not the Arduino board, so it does not support the UNO either.

Wiring notes

The pin table below is for the ESP32 (including ESP32-S and ESP-WROOM-32 modules). For other chips, see the table at the end of this section.

Unplug the USB cable before wiring or changing wires. A wrong voltage or a short circuit can destroy the board.

  • GPIO pins only accept 3.3V: do not connect 5V signals straight to a GPIO.
  • Do not drive high-current parts directly: motors, long LED strips and the like need an external supply or driver module. With an external supply, connect its GND to the ESP32's.
  • Check the pin numbers: numbers in programs are GPIO numbers, so compare them with the markings on the board or the pinout.
PinsAdviceWhy
GPIO 6–11Do not useConnected to the internal flash, so wiring them can stop the board working. GPIO 9 and 10, marked RX1 and TX1 on the pinout, are included.
GPIO 34, 35, 36, 39Input onlyThey cannot output, and have no internal pull-up or pull-down.
GPIO 25–27, GPIO 0, 2, 4, 12–15No analog with Wi-FiThese are ADC2 pins, which cannot read analog values while Wi-Fi is on. Use GPIO 32–39 for analog input.
GPIO 0, 2, 5, 12, 15Use with careTheir levels at power-up affect booting. If GPIO 12 is high at power-up, the board may not start.
GPIO 1, 3AvoidUsed by the USB serial port, so other parts here interfere with uploading and the monitor.
GPIO 4, 13, 16–19, 21–23, 25–27, 32, 33Good first choiceLeast likely to conflict for general digital input and output (GPIO 21 and 22 are often used for I2C).

Parts and sensors

This list is not a limit. Parts not listed here can also be used, as long as MicroPython can control them. Tell Gemini the full model and wiring pins, and follow the notes below when wiring.

  • TestedTested successfully on a real board.
  • ExampleThe site has a built-in example. Its program has run on simulated hardware, but not yet with the real part.
  • FirmwareThe firmware has what is needed, so you can program it directly, but there is no dedicated example and it has not been tested.

The OLED, LCD and MAX7219 need nothing extra installed. The firmware has no driver for these three parts, so their examples include the driver in the same main.py. Just choose the example and upload it. This has nothing to do with the CP210x and CH340 USB drivers on your computer.

Tips for asking Gemini

  • State the model and pins: for example, "MAX7219 8×8 LED matrix, DIN on GPIO 23, CLK on GPIO 18, CS on GPIO 5".
  • When a module is missing: an ImportError means the program uses a module the firmware lacks. Ask Gemini to "put this part's driver in the same main.py as the main program", or upload the module's file to the board with Board files.
  • Name the language: ask for MicroPython v1.29.0, not Arduino C++. The site's "Gemini prompts" → "Write a new program" already includes these requirements.

Advanced examples (21–26): 22, 23, 25 and 26 all use the wiring of example 2, so one setup covers them all. The interrupt and timer examples turn their interrupt or timer off when you press "Stop"; otherwise the LED would keep changing after the program stopped. ESP-NOW needs two or more boards, each running the same program. Use "Upload and run" for deep sleep; after waking, the board gives you 5 seconds to press "Stop". Boards with built-in USB (S2, S3, C3) drop the connection while asleep; connect again after they wake.
