Learning path

The 38 examples are arranged in three levels: beginner, intermediate and advanced. Work through them in order to learn step by step. Click an example's name to load it into the editor; you are asked first whether to replace the current program. Each step has a "Try changing it" task with no single right answer. If a change breaks the program, just load the example again. When you do not understand a program, use the explain option in Gemini prompts to have Gemini explain it.

For teachers: the suggested times assume 50-minute lessons, including wiring and the "Try changing it" tasks, but not students' own projects. The first lesson also needs time to install the driver and firmware, so you may want to install the firmware on the boards before class. The intermediate level has many sensors; if you are short of parts, give each group a different sensor and have them share what they learned.

Beginner: make LEDs and a buzzer come alive

  • By the end you can: connect the board, upload and run programs, and read the monitor's output and error notes; control LEDs and a buzzer with digital input and output, PWM and analog readings.
  • Suggested time: about 4 lessons.
  • Parts: an ESP32 board and a USB data cable, a breadboard, jumper wires, an LED, a 220Ω resistor, a push button, a 10kΩ potentiometer and a passive buzzer.
  • Site features used: Upload and run, Run (no save), the monitor and error notes, and the REPL.
  • 1. Blink an LED: control a pin with Pin.OUT, repeat forever with while True, and pause with time.sleep. Also compare "Run (no save)" with "Upload and run".Try changing it: make the interval 0.2 seconds, then make a rhythm of "on for 0.2 seconds, off for 1 second".
  • 2. Button-controlled LED: read a button with Pin.IN and Pin.PULL_UP, and compare two readings in a row to catch the moment it is pressed.Try changing it: make the LED light only while the button is held down.
  • 3. Breathing LED (PWM): set the brightness with PWM's duty_u16, and change the value step by step with for and range.Try changing it: make the breathing half as fast, then stop it at 50% brightness.
  • 4. Potentiometer LED dimmer: read an analog voltage with ADC as a number from 0 to 65535, and pass it to PWM.Try changing it: reverse it, so turning the knob further makes the LED dimmer.
  • 5. Twinkle Twinkle on a passive buzzer: the frequency sets the pitch; a dictionary holds the note names and a list holds the tune.Try changing it: make BEAT_MS smaller to speed the song up, then change SONG to "Frère Jacques" (C D E C, C D E C, E F G, E F G).

Intermediate: sensors and displays

  • By the end you can: read light, motion, distance, temperature and humidity sensors and watch their values on a chart; show results on an OLED, an LCD and lights; and check wiring problems with an I2C scan.
  • Suggested time: about 8 lessons.
  • Parts: an SG90 servo and an external 5V supply, a photoresistor and a 10kΩ resistor, an HC-SR501, an active buzzer module, an HC-SR04 with 1kΩ and 2kΩ resistors for the divider, a DHT11, a DS18B20 (a bare sensor needs a 4.7kΩ resistor), an SSD1306 OLED or I2C LCD 1602, a WS2812 strip and a MAX7219 matrix.
  • Site features used: Charts and CSV, Board files, "Write a new program" in Gemini prompts, and Wiring notes.
  • 6. SG90 servo sweep: set the angle by the width of a 50 Hz pulse, and write your own function, set_angle. The servo needs an external 5V supply.Try changing it: make it swing only between 45 and 135 degrees.
  • 7. Automatic night light (photoresistor): read a sensor, then use a threshold to decide whether to turn the light on.Try changing it: open the chart to watch the light level, and find the DARK_LEVEL that suits your room.
  • 8. Motion alarm (HC-SR501): print only when the state changes, so the monitor is not flooded.Try changing it: when someone is detected, make the buzzer beep on and off instead of sounding all the time.
  • 9. Ultrasonic distance (HC-SR04): work out the distance from the echo's travel time; the 5V signal must go through a divider before it reaches the ESP32.Try changing it: print "Too close!" when the distance is under 10 cm, then add an LED or buzzer warning.
  • 10. DHT11 temperature and humidity (monitor): import a sensor module, and handle failed readings with try and except.Try changing it: open the chart and breathe on the sensor to see how the humidity changes, then export a CSV and draw a chart in a spreadsheet.
  • 11. DS18B20 thermometer: 1-Wire communication, where one wire can carry several sensors.Try changing it: convert the temperature to Fahrenheit and print it next to Celsius.
  • 21. I2C scan (find device addresses): I2C tells devices apart by address; before using a display, check that the board can find it.Try changing it: connect an OLED and an LCD to the same SDA and SCL, and see whether both addresses show up.
  • 13. SSD1306 OLED display: text and lines are drawn in memory first, and the screen changes only when show() is called.Try changing it: add a line with your name, then draw a border with oled.rect().
  • 14. I2C LCD 1602 display: choose where text goes with move_to(column, row).Try changing it: show the seconds as minutes and seconds, such as 01:05.
  • 12. WS2812 RGB LED rainbow: a colour is three numbers (red, green, blue), and the strip changes only when write() is called.Try changing it: make the whole strip show red, green and blue in turn.
  • 15. MAX7219 LED matrix: draw an 8×8 picture with binary numbers made of 0s and 1s.Try changing it: design your own picture, such as an arrow, and add it to the slideshow.

Advanced: several things at once, and going online

  • By the end you can: use interrupts, timers and asyncio to make a program handle several things at once; connect the board to phones and online services, and read and control it from a phone dashboard; and build battery-saving or multi-board projects.
  • Suggested time: about 12 lessons.
  • Parts: the button and LED from example 2, a DHT11, a 10kΩ potentiometer, a 2.4GHz Wi-Fi network and a phone. The optional examples 30–38 also need a WS2812 strip, an SSD1306 OLED, a motor driver and a small car. The Telegram example needs a Telegram account, the Google Sheets example needs a Google account, and ESP-NOW needs two or more boards.
  • Site features used: the explain option in Gemini prompts, Phone and voice control, Phone dashboard, Google Sheets, and Privacy and safety (take care when a program holds a Wi-Fi password).
  • 22. Button interrupt (IRQ): the interrupt handler runs the moment the button is pressed and only sets a flag; ticks_diff filters out bounce.Try changing it: make the main loop wait 5 seconds, and check that no press is missed even when you press quickly several times.
  • 23. Timer blinks the LED by itself: a timer calls a function on a schedule while the main program does something else; finally cleans up.Try changing it: add a second timer that prints a message on the monitor every 3 seconds.
  • 26. asyncio: three things at once: asyncio means "asynchronous input/output": while one task waits, another runs. With async def and await, several tasks take turns running.Try changing it: add a fourth task that prints the free memory from gc.mem_free() every 5 seconds.
  • 16. Phone-controlled LED (same Wi-Fi): join Wi-Fi, make the board a web server, and use asyncio to serve the page and blink at the same time.Try changing it: add a "fast blink" button to the page.
  • 18. DHT11 humidity alarm: the phone page asks the board for JSON data every 2 seconds.Try changing it: change the alarm threshold from 50% to a number that suits your room.
  • 17. Voice-controlled LED (MQTT): send and receive messages across different networks through an online MQTT server.Try changing it: add a button that toggles the LED and reports the new state, so the voice control page updates too.
  • 27. Dashboard basics: LED switch and button: create widgets on the phone with dash, send values to the phone with .set(), and read the phone's switch with .value.Try changing it: add a board.text("Message") that says "Someone pressed it!" when the button is pressed.
  • 28. DHT11 dashboard: one value can go to a gauge and a chart at once, and color= picks a gauge's colour; the sensor is read every 3 seconds by checking the time, while board.check() keeps running. Breathing on the sensor changes the humidity the most.Try changing it: add a board.led("Too hot", color="red") that lights up above HOT.
  • 29. Knob and phone slider both dim an LED: the phone's slider and button control the board; when the knob turns, the board moves the phone's slider to match with .set(), and the last one moved wins.Try changing it: add an "Off" button that sets the slider to 0.
  • 30. Pick a colour for an RGB LED: the colour is (red, green, blue), three numbers from 0 to 255, used the same way as the strip in example 12.Try changing it: add a "Rainbow" switch that makes the strip change colour by itself.
  • 31. Phone-controlled car: two PWM pins set one motor's direction and speed; the direction keys move the car only while held, and the board stops the car if the phone drops off.Try changing it: make turns smoother by slowing one side instead of reversing it.
  • 32. Menu switches LED modes: work out the blinking and breathing brightness from time.ticks_ms() instead of waiting with time.sleep.Try changing it: add an "SOS" mode to the menu: three short, three long, three short.
  • 33. Send text to the OLED: .changed() updates the screen only for new text, and long text is cut into lines of 16 characters.Try changing it: show on the OLED's bottom line how many messages have arrived.
  • 34. Doorbell alert on the phone: an alert goes out only when it happens and is never kept; the phone and the board can call each other.Try changing it: use the motion sensor from example 8 instead, and tell the phone when someone walks past.
  • 35. Set a humidity limit from the phone: board.number() lets the phone set a limit, and .changed() tells the board it changed; the reading is compared with the newest limit every time round, so experiments need no code changes.Try changing it: add a temperature limit too, and light the LED only when both are exceeded.
  • 36. Temperature and humidity log: board.log() adds each reading as a row and the phone adds the time; a number setting sets how often.Try changing it: record for 10 minutes, download the CSV, and chart the humidity in a spreadsheet.
  • 37. Phone spirit level: board.tilt() reads the phone's tilt, with tilt.x and tilt.y from -100 to 100; the OLED is redrawn only when something changed, so it does not flicker.Try changing it: light the LED from example 2 when the phone is level.
  • 38. Phone joystick car: adding and subtracting the joystick's forward and turn amounts gives the speed of each wheel; near the centre the car stays still, so a shaky finger does not move it.Try changing it: drive with board.tilt() instead, by tilting the phone.
  • 19. Telegram bot LED: call an online API over HTTPS; the button's interrupt only sets a flag and leaves network work to the main program.Try changing it: add a /blink command that blinks the LED 5 times.
  • 20. Log DHT11 data to Google Sheets: put the readings in the address's parameters and send them to Apps Script, which writes them to the sheet.Try changing it: set SEND_SECONDS to 10 for testing, then draw a line chart in the sheet from the data collected.
  • 24. Deep sleep with timed wake-ups: the board uses almost no power while asleep, RTC memory keeps data during sleep, and waking up is like restarting.Try changing it: read the DHT11 once on each wake-up before sleeping again, to make a battery-saving temperature logger.
  • 25. ESP-NOW between boards: boards send messages straight to each other without a Wi-Fi router.Try changing it: send the number of presses instead, and have the receiving boards print it on the monitor.

After the advanced level, pick a challenge project and combine several examples into a complete project of your own.
