本網站採用 MicroPython，用 Python 語法寫程式，不是 Arduino C++。開發板要先安裝 MicroPython 韌體，安裝時會清除板子上原有的 Arduino 程式。Arduino 程式不能直接執行，貼上時畫面會出現提示，可以複製提示詞請 Gemini 改寫。兩者的差異請看 MicroPython 與 Arduino 的差異。

本網站目前是測試 Beta 版，仍在持續開發中。開發板和範例的組合很多，尚未逐一實測，使用時可能會遇到問題。如果發現錯誤，或有希望新增的功能，歡迎寫信告訴我。

開始使用

這個網站不用安裝 Arduino IDE，也不需要設定開發環境。請用電腦版 Chrome 或 Edge 開啟，用能傳輸資料的 USB 線接上開發板。

  1. 安裝驅動程式：電腦找不到開發板時才需要；USB 直接接 S2、S3、C3 晶片的板子通常不用裝。板子上的 USB 晶片是 CP2102 就裝 CP210x 驅動，是 CH340 就裝 CH340 驅動。編輯器右上角的「設定與說明」也有這些連結，以及腳位圖、語音控制頁、語言、風格和字體設定。
  2. 連接開發板：先關閉 Arduino IDE 這類會佔用序列埠的程式，再按「連接開發板」，選擇跳出的序列埠。
  3. 安裝韌體：第一次使用，或燒錄過 Arduino 程式時才需要。按「安裝韌體」後，板子上原有的程式和檔案都會被清除，安裝期間不要拔 USB 線。USB 直接接晶片的板子，裝完要按一下 RST 鍵並重新連接。
  4. 準備程式：選內建範例，或按「Gemini 提示詞」→「寫新程式」，填入接線和功能後貼給 Gemini，再把產生的 MicroPython 程式貼回編輯器。
  5. 上傳並執行：按「上傳並執行」，程式會存成板子上的 main.py，之後通電就會自動執行。監控窗第一行會顯示程式大小和上傳花了幾秒，接著是程式的輸出和錯誤訊息。
  6. 只是試試看：按「執行（不存檔）」或 F5，程式會直接在板子的記憶體裡執行，不會存成 main.py，見執行（不存檔）。

學習路徑

26 個範例分成初階、中階、進階三級，照順序做就能一步一步學會。點範例名稱會把它載入編輯器，載入前會先問你要不要取代目前的程式。每一步都有「動手改改看」，沒有標準答案，改壞了重新載入範例就好。看不懂程式時，可以用 Gemini 提示詞的「解說程式」請 Gemini 說明。

初階：讓 LED 和蜂鳴器動起來

  • 學完能做到：連接開發板、上傳和執行程式，看懂監控窗的輸出和錯誤提示；用數位輸出入、PWM 和類比讀值控制 LED 和蜂鳴器。
  • 建議時數：約 4 節。
  • 材料：ESP32 開發板和能傳資料的 USB 線、麵包板、杜邦線、LED、220Ω 電阻、按鈕、10kΩ 可變電阻、無源蜂鳴器。
  • 用到的網站功能：上傳並執行、執行（不存檔）、監控窗和錯誤提示、REPL 即時指令。
  • 1. LED 閃爍：用 Pin.OUT 控制腳位、while True 一直重複、time.sleep 暫停。順便比較「執行（不存檔）」和「上傳並執行」的差別。動手改改看：把間隔改成 0.2 秒；再試著做出「亮 0.2 秒、暗 1 秒」的節奏。
  • 2. 按鈕開關 LED：用 Pin.IN 和 Pin.PULL_UP 讀按鈕，比較前後兩次的狀態，找出「剛按下去」的那一刻。動手改改看：改成「按住才亮，放開就暗」。
  • 3. 呼吸燈（PWM）：用 PWM 的 duty_u16 調整亮度，用 for 和 range 一步一步改變數值。動手改改看：讓呼吸慢一倍；再改成最亮只到 50%。
  • 4. 可變電阻調亮度：用 ADC 讀類比電壓，得到 0 到 65535 的數字，再交給 PWM。動手改改看：反過來，旋鈕轉越多，LED 越暗。
  • 5. 無源蜂鳴器播放小星星：頻率決定音高，用字典存音名、用串列存旋律。動手改改看：把 BEAT_MS 改小讓歌變快；再把 SONG 換成「兩隻老虎」（C D E C、C D E C、E F G、E F G）。

中階：感測器和顯示器

  • 學完能做到：讀取光線、人體、距離、溫濕度等感測器，用圖表觀察數值；把結果顯示在 OLED、LCD 和燈光上；接線有問題時會用 I2C 掃描檢查。
  • 建議時數：約 8 節。
  • 材料：SG90 伺服馬達和外部 5V 電源、光敏電阻和 10kΩ 電阻、HC-SR501、有源蜂鳴器模組、HC-SR04 和分壓用的 1kΩ、2kΩ 電阻、DHT11、DS18B20（裸元件要加 4.7kΩ 電阻）、SSD1306 OLED 或 I2C LCD 1602、WS2812 燈條、MAX7219 點矩陣。
  • 用到的網站功能：圖表與 CSV、板上檔案、Gemini 提示詞的「寫新程式」、接線注意事項。
  • 6. SG90 伺服馬達來回轉動：用 50 Hz 脈衝的寬度控制角度，自己寫函式 set_angle。馬達要用外部 5V 供電。動手改改看：改成只在 45 度到 135 度之間擺動。
  • 7. 光敏電阻自動夜燈：讀感測器，再用門檻決定要不要開燈。動手改改看：打開圖表看亮度變化，找出適合你教室的 DARK_LEVEL。
  • 8. 人體紅外線警報（HC-SR501）：狀態改變時才印出，監控窗才不會洗版。動手改改看：偵測到人時，讓蜂鳴器「嗶、嗶」地響，不要一直響。
  • 9. 超音波測距（HC-SR04）：量回音的時間來換算距離；5V 的訊號要先分壓才能接 ESP32。動手改改看：距離小於 10 公分時印出「太近了！」，再加上 LED 或蜂鳴器提醒。
  • 10. DHT11 溫濕度（監控窗）：匯入感測器模組，用 try 和 except 處理讀取失敗。動手改改看：打開圖表，對感測器呵一口氣，看濕度怎麼變化；再匯出 CSV，用試算表畫圖。
  • 11. DS18B20 溫度計：單線（1-Wire）通訊，一條線可以串好幾顆感測器。動手改改看：把溫度換算成華氏，和攝氏一起印出來。
  • 21. I2C 掃描（找出裝置位址）：I2C 用位址區分裝置；接顯示器前，先確認板子找得到它。動手改改看：把 OLED 和 LCD 接在同一組 SDA、SCL 上，看看能不能同時掃到兩個位址。
  • 13. SSD1306 OLED 顯示器：先在記憶體裡寫字、畫線，呼叫 show() 後畫面才會更新。動手改改看：多顯示一行你的名字，再用 oled.rect() 畫一個外框。
  • 14. I2C LCD 1602 顯示器：用 move_to(欄, 列) 決定文字的位置。動手改改看：把秒數改成「分:秒」的格式，例如 01:05。
  • 12. WS2812 全彩 LED 彩虹：用（紅, 綠, 藍）三個數字表示顏色，呼叫 write() 後燈條才會更新。動手改改看：讓整條燈一起輪流顯示紅、綠、藍。
  • 15. MAX7219 點矩陣：用 0 和 1 組成的二進位數字畫 8×8 的圖案。動手改改看：自己設計一個圖案，例如箭頭，加進輪播。

進階：同時做好幾件事，連上網路

  • 學完能做到：用中斷、計時器和 asyncio 讓程式同時處理好幾件事；讓板子和手機、雲端服務互動；做出省電或多塊板子合作的作品。
  • 建議時數：約 10 節。
  • 材料：範例 2 的按鈕和 LED、DHT11、2.4GHz 的 Wi-Fi、手機；Telegram 範例要 Telegram 帳號，Google 試算表範例要 Google 帳號；ESP-NOW 要兩塊以上的板子。
  • 用到的網站功能：Gemini 提示詞的「解說程式」、手機與語音控制、Google 試算表、隱私與安全（程式裡有 Wi-Fi 密碼時要注意）。
  • 22. 按鈕中斷（IRQ）：按鈕一按下就執行中斷函式，函式裡只做記號；用 ticks_diff 去除彈跳。動手改改看：把主程式的等待改成 5 秒，確認快速按好幾下也一下都沒漏。
  • 23. 計時器讓 LED 自己閃（Timer）：計時器定時呼叫函式，主程式同時做別的事；用 finally 收尾。動手改改看：再加一個計時器，每 3 秒在監控窗印一次訊息。
  • 26. asyncio 同時做三件事：用 async def 和 await 讓好幾個工作輪流執行。動手改改看：加第四個工作，每 5 秒用 gc.mem_free() 印出剩下多少記憶體。
  • 16. 手機控制 LED（同一個 Wi-Fi）：連上 Wi-Fi，讓板子當網頁伺服器，用 asyncio 同時處理網頁和閃爍。動手改改看：在網頁上多加一個「快閃」按鈕。
  • 18. DHT11 溫濕度警報：手機網頁每 2 秒向板子要一次 JSON 資料。動手改改看：把警報門檻從 50% 改成適合你教室的數字。
  • 17. 語音控制 LED（MQTT）：透過網路上的 MQTT 伺服器，在不同的 Wi-Fi 之間收發訊息。動手改改看：加上一顆按鈕，按下時切換 LED，並回報狀態，讓語音控制頁跟著更新。
  • 19. Telegram 機器人控制 LED：用 HTTPS 呼叫網路上的 API，按鈕用中斷做記號，網路工作留給主程式。動手改改看：加一個 /blink 指令，讓 LED 閃 5 下。
  • 20. DHT11 資料存到 Google 試算表：把資料放在網址參數裡，送給 Apps Script 寫進試算表。動手改改看：先把 SEND_SECONDS 改成 10 秒測試，再用收集到的資料在試算表畫一張折線圖。
  • 24. 深度睡眠定時醒來：睡著時幾乎不耗電，RTC 記憶體在睡眠時會保留資料，醒來就像重新開機。動手改改看：醒來時讀一次 DHT11 再去睡，做成省電的溫度記錄器。
  • 25. ESP-NOW 多塊板子互傳：板子之間直接傳訊息，不用經過 Wi-Fi 基地台。動手改改看：改成傳送「按了第幾次」，收到的板子在監控窗印出來。

執行（不存檔）和上傳並執行

「執行（不存檔）」會先停止目前的程式、清空上一次留下的變數，再把編輯器裡的程式送到板子的記憶體直接執行，不會存成 main.py。連接開發板時，也可以按 F5；沒有連接時，F5 照樣是重新整理網頁。

執行（不存檔）上傳並執行
速度比較快，不用寫檔也不用重新開機稍慢
重新啟動或拔掉電源後程式消失，板子回到原本的 main.py程式留在板子上，通電就自動執行
適合試東西、改參數、找錯誤完成的作品，或要離開電腦執行

程式寫壞了也不用擔心：按「重新啟動」或拔掉電源，板子就會執行原本的 main.py。試好之後，再按「上傳並執行」存到板子上。程式讓板子重新開機時（例如深度睡眠或 machine.reset()）也一樣，醒來後執行的是板子上的 main.py，監控窗會提示。

程式結束後查看變數

程式結束或按「停止」之後，變數還留在板子上，可以在監控窗下方的 REPL 輸入變數名稱，看最後的值。例如：

total = 0
for i in range(1, 11):
    total = total + i

執行完在 REPL 輸入 total，會看到 55；輸入 i 會看到 10。找錯誤時，這比到處加 print 方便。用「上傳並執行」時板子會重新開機，所以要用「執行（不存檔）」才能這樣看。

錯誤訊息裡的 File "<stdin>", line 3 指的是編輯器第 3 行，和 main.py 的行號一樣。「複製給 Gemini」照樣可以用。

Gemini 提示詞

網站會依你選的晶片寫好提示詞，複製後貼到 Gemini 就好。編輯器上方的「Gemini 提示詞」選單有兩項：

  • 寫新程式：請 Gemini 寫一份完整的 main.py。貼上後，把括號裡的接線和想做的功能改成你的，再送出。
  • 解說程式：看不懂範例或 Gemini 給的程式時使用。Gemini 會用簡單的中文說明程式在做什麼、要接哪些零件、執行後監控窗會看到什麼，再分段解說。每段都會標出行號，可以對照編輯器左邊的數字。

只想問其中幾行，先在編輯器選取那幾行，再打開選單，第二項會變成「解說選取的程式（第 5–12 行）」。整份程式也會一起附上，讓 Gemini 了解前後文。沒有選取時，解說整份程式。

另外兩種提示詞會在需要時出現：程式出錯時，錯誤提示卡上的「複製給 Gemini」會附上錯誤訊息請 Gemini 修正；貼上 Arduino 程式時，提示列上的按鈕會請 Gemini 改寫成 MicroPython。

這些提示詞都會自動隱藏常見的 Wi-Fi 密碼和 Token 寫法，但不保證全部偵測得到，見隱私與安全。

MicroPython 與 Arduino 的差異

用 REPL 和開發板對話

REPL 是 Read-Eval-Print Loop 的縮寫，意思是讀取指令、執行、印出結果，然後重複。平常的 main.py 是寫好整份程式再上傳；REPL 則是說一句、回一句，很適合用來測接線、試指令和找錯誤。

這裡輸入的指令會直接在板子上執行，但不會存進 main.py。重新啟動或上傳程式後，變數和指令的效果都會消失。

開始使用

  1. 按「連接開發板」。連接時，板子上正在執行的程式會停止，監控窗會出現 >>> 提示符號。
  2. 如果程式正在執行（例如剛按完「上傳並執行」），先按「停止」。
  3. 在監控窗下方的輸入框打指令，按 Enter 送出。

動手試試看

照順序輸入下面的指令。第二段會用到 GPIO 2，也就是常見 ESP32 開發板的板載 LED；其他晶片或板子請改成自己的腳位。

1 + 1

from machine import Pin
led = Pin(2, Pin.OUT)
led.value(1)
led.value(0)

import os
os.listdir()

    print(i)

用圖表看感測器數值

監控窗右上角可以切換「文字」和「圖表」。切到「圖表」時，程式印出的數字會畫成折線圖，很適合觀察溫度變化、旋鈕轉動或距離遠近。不管停在哪一頁，資料都會持續記錄，切回來不會漏掉。

怎麼印才畫得出來

程式這樣印圖上出現
print("溫度:", t)一條「溫度」線
print("溫度:", t, "°C 濕度:", h, "%")「溫度」和「濕度」兩條線，數字後面的單位會略過
print(t, h)只印數字時，依順序叫做「數值1」、「數值2」
  • 名稱是冒號（或等號）前面的一個詞，中間不能有空格。例如 室內溫度: 可以；room temp: 只會取 temp。
  • 沒有數字的行、錯誤訊息、>>> 指令列，以及重新啟動時晶片印的系統訊息都不會畫。最多畫 8 條線。
  • 範例 4「可變電阻調亮度」、7「光敏電阻自動夜燈」、9「超音波測距（HC-SR04）」、10「DHT11 溫濕度（監控窗）」和 11「DS18B20 溫度計」不用修改，就能直接畫圖。這些範例開頭的註解也寫了怎麼玩，例如轉旋鈕、遮住光敏電阻或對 DHT11 哈氣。

不接任何元件也能試。上傳下面的程式，再切到「圖表」，會看到兩條波浪線。

管理板子上的檔案

連接開發板後，按編輯器上方的「板上檔案」，就能看到板子裡有哪些檔案，也可以下載、上傳和刪除，不用另外安裝 Thonny 或 mpremote。

打開「板上檔案」時，板子上正在執行的程式會停止。關掉視窗後程式還是停著，按監控窗的「重新啟動」就會再執行 main.py。

可以做什麼

操作功能
點資料夾名稱進入資料夾，例如 lib。上方的路徑可以點回上一層
開到編輯器把 100 KB 以內的文字檔（例如 .py、.txt、.csv、.json）放進編輯器，會先詢問
下載把檔案存到電腦
刪除刪除前會先詢問。資料夾要先清空才能刪
從電腦上傳檔案…上傳到目前所在的資料夾，可以一次選好幾個，也可以直接把檔案拖進視窗。同名檔案會先問要不要覆蓋
把編輯器內容存成…輸入檔名，把編輯器裡的程式存成那個檔案，例如 mylib.py

視窗右上角會顯示板子還剩多少空間。上傳和下載都會用 SHA-256 檢查檔案有沒有傳錯；上傳失敗時，板子上原來的檔案不會被改到。

自己寫一個函式庫

  1. 在編輯器寫好函式： 
    def hello(name):
    print("哈囉,", name)
  2. 按「板上檔案」，再按「把編輯器內容存成…」，輸入 mylib.py。
  3. 關掉視窗，在編輯器寫主程式，按「上傳並執行」： 
    import mylib
mylib.hello("ESP32")

網路上找到的元件函式庫，例如 OLED 的 ssd1306.py，也可以用「從電腦上傳檔案…」放到板子的根目錄或 lib 資料夾，再用 import 匯入。

把 lib/ssd1306.py 這類檔案開到編輯器修改後，要用「把編輯器內容存成…」存回去。直接按「上傳並執行」會把它存成 main.py，取代原本的主程式。

  • 指定語言：說明要 MicroPython v1.29.0，不要 Arduino C++。網站的「Gemini 提示詞」→「寫新程式」已經包含這些要求。

接線注意事項

下面的腳位表適用於 ESP32（包含 ESP32-S、ESP-WROOM-32 模組），其他晶片請看本章最後的表格。

接線或改線前，請先拔掉 USB 線。接錯電壓或短路可能會燒毀開發板。

  • GPIO 只能接受 3.3V：不要把 5V 訊號直接接到 GPIO。
  • 不要直接驅動大電流元件：馬達、長燈條等要用外部電源或驅動模組。使用外部電源時，GND 要和 ESP32 接在一起。
  • 確認腳位編號：程式裡的編號是 GPIO 編號，請對照板子標示或腳位圖。
腳位建議原因
GPIO 6–11不要使用連接內部快閃記憶體，接線可能讓板子無法運作。腳位圖上的 GPIO 9、10 標示 RX1、TX1，也不要使用。
GPIO 34、35、36、39只能輸入不能輸出，也沒有內部上拉或下拉電阻。
GPIO 25–27、GPIO 0、2、4、12–15類比輸入避開這些是 ADC2 腳位，Wi-Fi 開啟時不能讀類比值。需要類比輸入請改用 GPIO 32–39。
GPIO 0、2、5、12、15小心使用開機時的電位會影響啟動。尤其 GPIO 12 開機時若被拉高，板子可能無法啟動。
GPIO 1、3避開USB 序列埠使用，接其他元件會影響上傳和監控窗。
GPIO 4、13、16–19、21–23、25–27、32、33一般優先選用用於一般數位輸入和輸出比較不會衝突（GPIO 21、22 常用於 I2C）。

手機與語音控制

網站有兩種手機網頁控制方式，也可以用本章最後的 Telegram 機器人控制：

開發板上的網頁語音控制頁（MQTT）
範例手機控制 LED、DHT11 溫濕度警報語音控制 LED（MQTT）
網址http://192.168.x.x（監控窗會顯示）語音控制頁
麥克風語音不能用，瀏覽器不允許 http:// 網址使用麥克風可以用（HTTPS）
網路需求手機和板子連同一個 Wi-Fi，不一定要能上網板子和手機都要能上網，不必同一個 Wi-Fi
校園網路影響禁止裝置互連時會打不開防火牆擋 1883 連接埠時，板子會連不上

語音控制步驟

  1. 範例選「語音控制 LED（MQTT）」，填入 Wi-Fi 名稱和密碼，按「上傳並執行」。
  2. 監控窗顯示「已連上 MQTT 伺服器」後，記下 MQTT 主題名稱。
  3. 開啟語音控制頁，輸入主題名稱後按「連線」。
  4. 按語音按鈕，允許使用麥克風，然後說「開燈」、「關燈」或「閃爍」。

語音不能用時，可以按開燈、關燈按鈕，或在文字指令欄用手機鍵盤的麥克風輸入。Windows 電腦也可以按 Win + H 語音輸入。

主題名稱和 MQTT Topic：你輸入的名稱會組成兩個 Topic。以 led-1 為例，指令走 esp32-mp-class/led-1/command，開發板回報走 esp32-mp-class/led-1/state，其他 MQTT 工具也可以訂閱或發布這兩個 Topic。

使用自己的 MQTT 伺服器：打開語音控制頁的「進階」，填入伺服器位址、WSS 連接埠、路徑、帳號和密碼；程式裡的 BROKER、MQTT_PORT、MQTT_USER、MQTT_PASSWORD 也要改成同一台。語音控制頁不會儲存密碼，重新整理後要再輸入一次。開發板預設走不加密的 1883 連接埠，帳號密碼可能被同網路的人看到，請使用這台伺服器專用的密碼。

Telegram 機器人

  1. 在 Telegram 搜尋 @BotFather，傳 /newbot，依指示取名後會拿到 Bot Token。
  2. 範例選「Telegram 機器人控制 LED」，填入 Wi-Fi 名稱、密碼和 BOT_TOKEN，按「上傳並執行」。
  3. 傳任一則訊息給你的機器人，監控窗會顯示 CHAT_ID。把號碼填進程式，再上傳一次。
  4. 傳 /on、/off 或 /status 控制 LED；按下按鈕時，手機會收到通知。

板子約每 2 秒查一次新訊息，反應會有幾秒延遲。只有 CHAT_ID 指定的聊天室能控制板子，開機前累積的舊指令不會執行。校園網路封鎖 Telegram 時，板子會連不上，可以改用手機熱點。

Wi-Fi 只支援 2.4GHz。ESP32 連不上 5GHz 網路。

把感測器資料存到 Google 試算表

範例「DHT11 資料存到 Google 試算表」每分鐘會把時間、溫度和濕度新增成一列。Google Apps Script 是免費服務，但要先設定一次。這個範例已用模擬硬體和模擬 Google 回應測試，尚未接實體 Google 試算表測試。

  1. 到 Google 試算表建立新檔案，在第一列輸入標題：時間、溫度、濕度。
  2. 點選「擴充功能」→「Apps Script」，把原本的內容換成下面的程式後儲存： 
    function doGet(e) {
  var temp = Number(e.parameter.temp);
  var hum = Number(e.parameter.hum);
  if (isNaN(temp) || isNaN(hum)) {
    return ContentService.createTextOutput("bad data");
  }
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  sheet.appendRow([new Date(), temp, hum]);
  return ContentService.createTextOutput("ok");
}
  3. 點選「部署」→「新增部署作業」，類型選「網頁應用程式」。執行身分選「我」，存取權選「所有人」，再依畫面完成授權。
  4. 複製部署後的網址，結尾是 /exec。先在瀏覽器網址列的網址後面加上 ?temp=25&hum=60 開啟，畫面顯示 ok、試算表多一列，就代表設定正確。測試完可以刪除這一列。
  5. 範例選「DHT11 資料存到 Google 試算表」，填入 Wi-Fi 名稱、密碼和 SCRIPT_URL，按「上傳並執行」。

網址等於試算表的寫入權限。知道網址的人都能新增資料，不要投影或分享。不小心外洩時，請到「部署」→「管理部署作業」封存這個部署，再建立新的部署。

學校的 Google 帳號可能不允許把存取權設成「所有人」，這時請改用個人帳號。之後修改 Apps Script，要在「管理部署作業」選編輯並發布新版本，才會生效。

隱私與安全

  • 程式碼：網站不會把程式碼上傳到伺服器。程式碼只存在這個瀏覽器和你的開發板上。GitHub 只提供網站檔案，可能記錄 IP 這類連線資訊，但收不到你的程式碼。
  • 瀏覽統計：網站用 GoatCounter 統計頁面瀏覽人次，頁尾顯示的是編輯器頁面的累計人次。每次開啟頁面時，只會送出頁面路徑、頁面標題和來源網站，GoatCounter 也會收到瀏覽器必然帶上的 IP 和瀏覽器資訊，用來估算不重複的訪客。統計不使用 Cookie，也不會送出程式碼、Wi-Fi 密碼、序列埠內容或 MQTT 主題名稱。
  • Wi-Fi 密碼：密碼寫在程式裡，所以會以明文存在瀏覽器和開發板的 main.py。使用共用電腦或借出開發板前，請先刪除密碼，做法見下方「共用電腦與開發板」。
  • 貼給 Gemini 前：「解說程式」、「複製給 Gemini」和「改寫成 MicroPython」會自動隱藏常見的 Wi-Fi、帳號密碼、Token 和 Apps Script 網址寫法，但不保證全部偵測得到。自己全選複製程式時不會隱藏，請先刪除密碼。
  • 截圖和投影：編輯器會顯示密碼，投影或分享畫面前請先遮住。上課建議使用專用 Wi-Fi 或手機熱點。
  • 語音控制：指令會經過公用 MQTT 伺服器，沒有加密保護和權限控管，知道主題名稱的人都能控制。只適合 LED 這類低風險實驗，不要控制插座或門鎖，也不要在主題名稱填入個人資料。
  • 語音辨識：語音由瀏覽器和其語音服務辨識，通常需要連網。
  • Telegram Bot Token：Token 等於機器人的密碼，拿到的人可以冒用機器人，不要投影或分享。不小心外洩時，請到 @BotFather 傳 /revoke 換一組。範例不驗證伺服器憑證，不要用來控制重要設備。

共用電腦與開發板

關閉網頁不會清除程式碼。程式碼和裡面的 Wi-Fi 密碼會留在瀏覽器，下一個用同一台電腦、同一個瀏覽器帳號的人打開網站就看得到。

離開電腦或交還開發板前，請照下面做：

  1. 想留下程式：先刪除程式裡的 Wi-Fi 名稱、密碼、MQTT 帳號密碼、Bot Token 和 Apps Script 網址，再按「下載 main.py」。下載的檔案不會自動隱藏這些資料。
  2. 清除瀏覽器：刪除編輯器裡的全部內容。編輯器會自動儲存，所以舊內容會一起被取代。
  3. 清除開發板：上傳不含密碼的程式，會覆蓋板子上的 main.py；其他含有密碼的檔案可以在板上檔案刪除。要清除板子上所有檔案，請重新安裝韌體。

電腦教室的還原卡通常會在重新開機後清除瀏覽器資料，但重新開機前，下一位使用者還是看得到。開發板不受還原卡影響，資料會一直留在板子上。

常見問題

安裝韌體時出現 Serial data stream stopped

這時通常還沒開始清除，板子沒有損壞，會繼續執行原本的程式。請重新整理網頁、拔掉再插回 USB 線，重新連接後再裝一次，實測的 CH340 板就是這樣裝好的。還是失敗時，改插電腦本體的 USB 孔、換一條 USB 線，或按住 IO0 鍵、按一下 EN 鍵、放開 IO0 鍵後再安裝。

晶片選錯了，上傳後板子會壞掉嗎？

選單選錯不會影響韌體，安裝時網站會自己偵測晶片。上傳的程式也不會改動韌體，但腳位可能不對。ESP32 選成 S2、S3 或 C3 時，範例可能用到 GPIO 6–11，板子可能當機或一直重新啟動。這種情況只要重新選對晶片和範例後上傳；上傳不了時，請按住 IO0 鍵重新安裝韌體。真正可能損壞板子的是接線，例如把 5V 接到 GPIO、電源短路，或腳位輸出時直接接到電源或 GND。

可以用 ESP32-CAM 拍照嗎？

目前不行。MicroPython 官方韌體沒有相機模組，要改用第三方編譯的韌體才能拍照，網站沒有內建。

ESP32-S2、S3、C3 安裝韌體時連不上，或裝完沒有反應

USB 直接接晶片的板子，重新啟動時序列埠會暫時消失。連不上時，請按住 BOOT 鍵、按一下 RST 鍵、放開 BOOT 鍵，再重新按「連接開發板」並安裝。裝完後按一下 RST 鍵，等 2 秒再連接。板子有兩個 USB 孔時，可以改接標示 UART 或 COM 的那一個。

按「連接開發板」後，清單裡沒有序列埠

先換一條確定能傳輸資料的 USB 線，有些線只能充電。接著確認已安裝對應的驅動程式，並重新插拔開發板。

連接失敗，或顯示序列埠被佔用

關閉 Arduino IDE 和其他分頁裡的本網站，一次只能有一個程式使用序列埠。

顯示「沒有偵測到 MicroPython」

第一次使用，或燒錄過 Arduino 程式時都會這樣。按「安裝韌體」即可，不用另外下載韌體。

安裝韌體時一直連不上

網站會自動重新連接，最多試 10 次，每一次都會寫在監控窗。10 次都失敗時，請按住板子上的 IO0（BOOT）鍵再按「安裝韌體」，開始寫入後就可以放開。有些板子的自動重置電路不太穩，按住 IO0 是最可靠的做法。回報問題時，請一起提供監控窗裡「連線紀錄」下面的內容。

顯示「這塊板子是 ESP32-xx，目前只支援 ESP32、ESP32-S2、S3 和 C3」

這塊板子的晶片不在支援範圍內，內建韌體不能用。請改用這四種晶片的開發板。

監控窗出現紅色的「程式發生錯誤」

按「複製給 Gemini」，把錯誤訊息和程式碼一起貼給 Gemini 修正，再把新程式貼回來上傳。

看不懂範例或 Gemini 給的程式

按「Gemini 提示詞」→「解說整份程式」，貼給 Gemini，它會分段解說並標出行號。只看不懂其中幾行，就先選取那幾行再打開選單，見 Gemini 提示詞。

顯示 Wi-Fi 連線失敗

確認名稱和密碼完全正確（包含大小寫），並確認是 2.4GHz 網路。

手機打不開 192.168.x.x 的網頁

確認手機和開發板連同一個 Wi-Fi，也關閉手機的行動數據試試。校園網路可能禁止裝置互連，可以改用手機熱點，或語音控制頁（MQTT）。

沒有跳出麥克風權限，語音不能用

確認開啟的是 HTTPS 的語音控制頁，不是 http://192.168.x.x。如果之前拒絕過，請到瀏覽器的網站設定改成允許。

語音控制頁顯示「開發板沒有回應」或「離線」

確認開發板程式正在執行、監控窗顯示已連上 MQTT 伺服器，以及頁面和程式裡的主題名稱完全相同。校園網路可能會擋 1883 連接埠，可以改用手機熱點測試。

語音控制頁顯示「MQTT 帳號或密碼不正確」

確認帳號密碼和伺服器設定相同，以及這個帳號有權限使用 esp32-mp-class/ 開頭的 Topic。密碼不會儲存，重新整理後要再輸入一次。

Google 試算表範例顯示「Google 沒有回傳 ok」

通常是部署時存取權沒有選「所有人」，或學校帳號不允許。請先用瀏覽器的無痕視窗開啟網址測試，應該要顯示 ok。資料沒有增加時，也請確認網址結尾是 /exec。

按下「停止」後，程式之後還會自動執行嗎？

會。「停止」只中斷目前的執行，main.py 還在板子上，下次通電或重新啟動時會再次執行。

用「執行（不存檔）」試好了，怎麼讓它通電就自動執行？

按「上傳並執行」，程式會存成 main.py。「執行（不存檔）」的程式只在記憶體裡，重新啟動或拔掉電源就會消失。
