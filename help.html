本網站採用 MicroPython，用 Python 語法寫程式，不是 Arduino C++。開發板要先安裝 MicroPython 韌體，安裝時會清除板子上原有的 Arduino 程式。Arduino 程式不能直接執行，貼上時畫面會出現提示，可以複製提示詞請 Gemini 改寫。兩者的差異請看 MicroPython 與 Arduino 的差異。

本網站目前是測試 Beta 版，仍在持續開發中。開發板和範例的組合很多，尚未逐一實測，使用時可能會遇到問題。如果發現錯誤，或有希望新增的功能，歡迎寫信告訴我。

開始使用

這個網站不用安裝 Arduino IDE，也不需要設定開發環境。請用電腦版 Chrome 或 Edge 開啟，用能傳輸資料的 USB 線接上開發板。

  1. 安裝驅動程式：電腦找不到開發板時才需要；USB 直接接 S2、S3、C3 晶片的板子通常不用裝。板子上的 USB 晶片是 CP2102 就裝 CP210x 驅動，是 CH340 就裝 CH340 驅動。編輯器右上角的「設定與說明」也有這些連結，以及腳位圖、語音控制頁、風格和字體設定。
  2. 連接開發板：先關閉 Arduino IDE 這類會佔用序列埠的程式，再按「連接開發板」，選擇跳出的序列埠。
  3. 安裝韌體：第一次使用，或燒錄過 Arduino 程式時才需要。按「安裝韌體」後，板子上原有的程式和檔案都會被清除，安裝期間不要拔 USB 線。USB 直接接晶片的板子，裝完要按一下 RST 鍵並重新連接。
  4. 準備程式：選內建範例，或按「複製 Gemini 提示詞」，填入接線和功能後貼給 Gemini，再把產生的 MicroPython 程式貼回編輯器。
  5. 上傳並執行：按「上傳並執行」，程式會存成板子上的 main.py，之後通電就會自動執行。輸出和錯誤訊息會顯示在序列埠監控窗。

MicroPython 與 Arduino 的差異

兩者都能控制 ESP32，沒有哪一個絕對比較好。本網站選擇 MicroPython，是因為不用安裝軟體，改完程式幾秒就能看到結果，錯誤訊息也容易看懂，適合課堂和快速實驗。

MicroPython（本網站）Arduino C++
語言Python，語法簡短，容易入門C++，要宣告型別，語法較嚴格
開發環境開啟瀏覽器就能使用，要先安裝一次韌體要安裝 Arduino IDE 和開發板套件，電腦還原後要重裝
修改後上傳不用編譯，通常幾秒完成每次都要編譯再燒錄，等待時間較長
找錯誤錯誤訊息會指出行號，也可以在監控窗直接輸入指令測試編譯時能先抓到語法錯誤，執行時的問題多半靠序列埠輸出追查
執行速度較慢，一般感測和控制通常夠用快很多，適合大量運算和高速處理
記憶體直譯器本身會佔用空間，可用的較少可用的較多，比較適合大型程式
時間精準度記憶體回收可能造成短暫停頓，不適合要求精準時序的工作時間控制較精準
函式庫常用功能已內建，其他模組可能要自己找程式碼數量很多，大部分模組都找得到
適合用途入門教學、搭配 AI 寫程式、感測器和物聯網實驗相機影像、高速訊號處理、大型或要長期穩定運作的專案

同一塊板子可以換來換去，只是一次只能用一種：用 Arduino IDE 燒錄後，MicroPython 和板子上的檔案會被覆蓋；想換回來，再到本網站按「安裝韌體」即可。

電子元件與感測器

下表不是限制清單。只要能用 MicroPython 控制，表上沒有的元件也可以使用。請把完整型號和接線腳位告訴 Gemini，再依下面的注意事項接線。

  • 已實測已接上實體開發板測試成功。
  • 有範例網站有內建範例，程式已用模擬硬體執行過，但還沒接實體元件測試。
  • 韌體支援韌體有所需功能，可以直接寫程式，但沒有專屬範例，也還沒實測。

OLED、LCD 和 MAX7219 不用另外安裝任何東西。韌體沒有內建這三種元件的控制程式，所以內建範例把控制程式和主程式寫在同一份 main.py，選範例後直接上傳即可。這和電腦上的 CP210x、CH340 USB 驅動程式無關。

接線注意事項

下面的腳位表適用於 ESP32（包含 ESP32-S、ESP-WROOM-32 模組），其他晶片請看本章最後的表格。

接線或改線前，請先拔掉 USB 線。接錯電壓或短路可能會燒毀開發板。

  • GPIO 只能接受 3.3V：不要把 5V 訊號直接接到 GPIO。
  • 不要直接驅動大電流元件：馬達、長燈條等要用外部電源或驅動模組。使用外部電源時，GND 要和 ESP32 接在一起。
  • 確認腳位編號：程式裡的編號是 GPIO 編號，請對照板子標示或腳位圖。
腳位建議原因
GPIO 6–11不要使用連接內部快閃記憶體，接線可能讓板子無法運作。腳位圖上的 GPIO 9、10 標示 RX1、TX1，也不要使用。
GPIO 34、35、36、39只能輸入不能輸出，也沒有內部上拉或下拉電阻。
GPIO 25–27、GPIO 0、2、4、12–15類比輸入避開這些是 ADC2 腳位，Wi-Fi 開啟時不能讀類比值。需要類比輸入請改用 GPIO 32–39。
GPIO 0、2、5、12、15小心使用開機時的電位會影響啟動。尤其 GPIO 12 開機時若被拉高，板子可能無法啟動。
GPIO 1、3避開USB 序列埠使用，接其他元件會影響上傳和監控窗。
GPIO 4、13、16–19、21–23、25–27、32、33一般優先選用用於一般數位輸入和輸出比較不會衝突（GPIO 21、22 常用於 I2C）。

語音控制步驟

  1. 範例選「語音控制 LED（MQTT）」，填入 Wi-Fi 名稱和密碼，按「上傳並執行」。
  2. 監控窗顯示「已連上 MQTT 伺服器」後，記下 MQTT 主題名稱。
  3. 開啟語音控制頁，輸入主題名稱後按「連線」。
  4. 按語音按鈕，允許使用麥克風，然後說「開燈」、「關燈」或「閃爍」。

語音不能用時，可以按開燈、關燈按鈕，或在文字指令欄用手機鍵盤的麥克風輸入。Windows 電腦也可以按 Win + H 語音輸入。

主題名稱和 MQTT Topic：你輸入的名稱會組成兩個 Topic。以 led-1 為例，指令走 esp32-mp-class/led-1/command，開發板回報走 esp32-mp-class/led-1/state，其他 MQTT 工具也可以訂閱或發布這兩個 Topic。

使用自己的 MQTT 伺服器：打開語音控制頁的「進階」，填入伺服器位址、WSS 連接埠、路徑、帳號和密碼；程式裡的 BROKER、MQTT_PORT、MQTT_USER、MQTT_PASSWORD 也要改成同一台。語音控制頁不會儲存密碼，重新整理後要再輸入一次。開發板預設走不加密的 1883 連接埠，帳號密碼可能被同網路的人看到，請使用這台伺服器專用的密碼。

Telegram 機器人

  1. 在 Telegram 搜尋 @BotFather，傳 /newbot，依指示取名後會拿到 Bot Token。
  2. 範例選「Telegram 機器人控制 LED」，填入 Wi-Fi 名稱、密碼和 BOT_TOKEN，按「上傳並執行」。
  3. 傳任一則訊息給你的機器人，監控窗會顯示 CHAT_ID。把號碼填進程式，再上傳一次。
  4. 傳 /on、/off 或 /status 控制 LED；按下按鈕時，手機會收到通知。

板子約每 2 秒查一次新訊息，反應會有幾秒延遲。只有 CHAT_ID 指定的聊天室能控制板子，開機前累積的舊指令不會執行。校園網路封鎖 Telegram 時，板子會連不上，可以改用手機熱點。

Wi-Fi 只支援 2.4GHz。ESP32 連不上 5GHz 網路。

把感測器資料存到 Google 試算表

範例「DHT11 資料存到 Google 試算表」每分鐘會把時間、溫度和濕度新增成一列。Google Apps Script 是免費服務，但要先設定一次。這個範例已用模擬硬體和模擬 Google 回應測試，尚未接實體 Google 試算表測試。

  1. 到 Google 試算表建立新檔案，在第一列輸入標題：時間、溫度、濕度。
  2. 點選「擴充功能」→「Apps Script」，把原本的內容換成下面的程式後儲存： 
    function doGet(e) {
  var temp = Number(e.parameter.temp);
  var hum = Number(e.parameter.hum);
  if (isNaN(temp) || isNaN(hum)) {
    return ContentService.createTextOutput("bad data");
  }
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  sheet.appendRow([new Date(), temp, hum]);
  return ContentService.createTextOutput("ok");
}
  3. 點選「部署」→「新增部署作業」，類型選「網頁應用程式」。執行身分選「我」，存取權選「所有人」，再依畫面完成授權。
  4. 複製部署後的網址，結尾是 /exec。先在瀏覽器網址列的網址後面加上 ?temp=25&hum=60 開啟，畫面顯示 ok、試算表多一列，就代表設定正確。測試完可以刪除這一列。
  5. 範例選「DHT11 資料存到 Google 試算表」，填入 Wi-Fi 名稱、密碼和 SCRIPT_URL，按「上傳並執行」。

網址等於試算表的寫入權限。知道網址的人都能新增資料，不要投影或分享。不小心外洩時，請到「部署」→「管理部署作業」封存這個部署，再建立新的部署。

學校的 Google 帳號可能不允許把存取權設成「所有人」，這時請改用個人帳號。之後修改 Apps Script，要在「管理部署作業」選編輯並發布新版本，才會生效。

隱私與安全

  • 程式碼：網站不會把程式碼上傳到伺服器。程式碼只存在這個瀏覽器和你的開發板上。GitHub 只提供網站檔案，可能記錄 IP 這類連線資訊，但收不到你的程式碼。
  • 瀏覽統計：網站用 GoatCounter 統計頁面瀏覽人次，頁尾顯示的是編輯器頁面的累計人次。每次開啟頁面時，只會送出頁面路徑、頁面標題和來源網站，GoatCounter 也會收到瀏覽器必然帶上的 IP 和瀏覽器資訊，用來估算不重複的訪客。統計不使用 Cookie，也不會送出程式碼、Wi-Fi 密碼、序列埠內容或 MQTT 主題名稱。
  • Wi-Fi 密碼：密碼寫在程式裡，所以會以明文存在瀏覽器和開發板的 main.py。使用共用電腦或借出開發板前，請先刪除密碼，做法見下方「共用電腦與開發板」。
  • 貼給 Gemini 前：「複製給 Gemini」和「改寫成 MicroPython」會自動隱藏常見的 Wi-Fi、帳號密碼、Token 和 Apps Script 網址寫法，但不保證全部偵測得到。自己全選複製程式時不會隱藏，請先刪除密碼。
  • 截圖和投影：編輯器會顯示密碼，投影或分享畫面前請先遮住。上課建議使用專用 Wi-Fi 或手機熱點。
  • 語音控制：指令會經過公用 MQTT 伺服器，沒有加密保護和權限控管，知道主題名稱的人都能控制。只適合 LED 這類低風險實驗，不要控制插座或門鎖，也不要在主題名稱填入個人資料。
  • 語音辨識：語音由瀏覽器和其語音服務辨識，通常需要連網。
  • Telegram Bot Token：Token 等於機器人的密碼，拿到的人可以冒用機器人，不要投影或分享。不小心外洩時，請到 @BotFather 傳 /revoke 換一組。範例不驗證伺服器憑證，不要用來控制重要設備。

共用電腦與開發板

關閉網頁不會清除程式碼。程式碼和裡面的 Wi-Fi 密碼會留在瀏覽器，下一個用同一台電腦、同一個瀏覽器帳號的人打開網站就看得到。

離開電腦或交還開發板前，請照下面做：

  1. 想留下程式：先刪除程式裡的 Wi-Fi 名稱、密碼、MQTT 帳號密碼、Bot Token 和 Apps Script 網址，再按「下載 main.py」。下載的檔案不會自動隱藏這些資料。
  2. 清除瀏覽器：刪除編輯器裡的全部內容。編輯器會自動儲存，所以舊內容會一起被取代。
  3. 清除開發板：上傳不含密碼的程式，會覆蓋板子上的 main.py；要清除板子上所有檔案，請重新安裝韌體。

電腦教室的還原卡通常會在重新開機後清除瀏覽器資料，但重新開機前，下一位使用者還是看得到。開發板不受還原卡影響，資料會一直留在板子上。

常見問題

安裝韌體時出現 Serial data stream stopped

這時通常還沒開始清除，板子沒有損壞，會繼續執行原本的程式。請重新整理網頁、拔掉再插回 USB 線，重新連接後再裝一次，實測的 CH340 板就是這樣裝好的。還是失敗時，改插電腦本體的 USB 孔、換一條 USB 線，或按住 IO0 鍵、按一下 EN 鍵、放開 IO0 鍵後再安裝。

晶片選錯了，上傳後板子會壞掉嗎？

選單選錯不會影響韌體，安裝時網站會自己偵測晶片。上傳的程式也不會改動韌體，但腳位可能不對。ESP32 選成 S2、S3 或 C3 時，範例可能用到 GPIO 6–11，板子可能當機或一直重新啟動。這種情況只要重新選對晶片和範例後上傳；上傳不了時，請按住 IO0 鍵重新安裝韌體。真正可能損壞板子的是接線，例如把 5V 接到 GPIO、電源短路，或腳位輸出時直接接到電源或 GND。

可以用 ESP32-CAM 拍照嗎？

目前不行。MicroPython 官方韌體沒有相機模組，要改用第三方編譯的韌體才能拍照，網站沒有內建。

ESP32-S2、S3、C3 安裝韌體時連不上，或裝完沒有反應

USB 直接接晶片的板子，重新啟動時序列埠會暫時消失。連不上時，請按住 BOOT 鍵、按一下 RST 鍵、放開 BOOT 鍵，再重新按「連接開發板」並安裝。裝完後按一下 RST 鍵，等 2 秒再連接。板子有兩個 USB 孔時，可以改接標示 UART 或 COM 的那一個。

按「連接開發板」後，清單裡沒有序列埠

先換一條確定能傳輸資料的 USB 線，有些線只能充電。接著確認已安裝對應的驅動程式，並重新插拔開發板。

連接失敗，或顯示序列埠被佔用

關閉 Arduino IDE 和其他分頁裡的本網站，一次只能有一個程式使用序列埠。

顯示「沒有偵測到 MicroPython」

第一次使用，或燒錄過 Arduino 程式時都會這樣。按「安裝韌體」即可，不用另外下載韌體。

安裝韌體時一直連不上

按住板子上的 IO0（BOOT）鍵再重試，開始寫入後就可以放開。

顯示「這塊板子是 ESP32-xx，目前只支援 ESP32、ESP32-S2、S3 和 C3」

這塊板子的晶片不在支援範圍內，內建韌體不能用。請改用這四種晶片的開發板。

監控窗出現紅色的「程式發生錯誤」

按「複製給 Gemini」，把錯誤訊息和程式碼一起貼給 Gemini 修正，再把新程式貼回來上傳。

顯示 Wi-Fi 連線失敗

確認名稱和密碼完全正確（包含大小寫），並確認是 2.4GHz 網路。

手機打不開 192.168.x.x 的網頁

確認手機和開發板連同一個 Wi-Fi，也關閉手機的行動數據試試。校園網路可能禁止裝置互連，可以改用手機熱點，或語音控制頁（MQTT）。

沒有跳出麥克風權限，語音不能用

確認開啟的是 HTTPS 的語音控制頁，不是 http://192.168.x.x。如果之前拒絕過，請到瀏覽器的網站設定改成允許。

語音控制頁顯示「開發板沒有回應」或「離線」

確認開發板程式正在執行、監控窗顯示已連上 MQTT 伺服器，以及頁面和程式裡的主題名稱完全相同。校園網路可能會擋 1883 連接埠，可以改用手機熱點測試。

語音控制頁顯示「MQTT 帳號或密碼不正確」

確認帳號密碼和伺服器設定相同，以及這個帳號有權限使用 esp32-mp-class/ 開頭的 Topic。密碼不會儲存，重新整理後要再輸入一次。

Google 試算表範例顯示「Google 沒有回傳 ok」

通常是部署時存取權沒有選「所有人」，或學校帳號不允許。請先用瀏覽器的無痕視窗開啟網址測試，應該要顯示 ok。資料沒有增加時，也請確認網址結尾是 /exec。

按下「停止」後，程式之後還會自動執行嗎？

會。「停止」只中斷目前的執行，main.py 還在板子上，下次通電或重新啟動時會再次執行。
