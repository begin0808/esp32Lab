手機與語音控制

網站有兩種手機網頁控制方式，也可以用本章最後的 Telegram 機器人控制。想在手機上同時看好幾個數值、用開關和滑桿控制板子，請看手機儀表板。

開發板上的網頁語音控制頁（MQTT）
範例手機控制 LED、DHT11 溫濕度警報語音控制 LED（MQTT）
網址http://192.168.x.x（監控窗會顯示）語音控制頁
麥克風語音不能用，瀏覽器不允許 http:// 網址使用麥克風可以用（HTTPS）
網路需求手機和板子連同一個 Wi-Fi，不一定要能上網板子和手機都要能上網，不必同一個 Wi-Fi
校園網路影響禁止裝置互連時會打不開防火牆擋 1883 連接埠時，板子會連不上

語音控制步驟

  1. 範例選「語音控制 LED（MQTT）」，填入 Wi-Fi 名稱和密碼，按「上傳並執行」。
  2. 監控窗顯示「已連上 MQTT 伺服器」後，記下 MQTT 主題名稱。
  3. 開啟語音控制頁，輸入主題名稱後按「連線」。
  4. 按語音按鈕，允許使用麥克風，然後說「開燈」、「關燈」或「閃爍」。

語音不能用時，可以按開燈、關燈按鈕，或在文字指令欄用手機鍵盤的麥克風輸入。Windows 電腦也可以按 Win + H 語音輸入。

主題名稱和 MQTT Topic：你輸入的名稱會組成兩個 Topic。以 led-1 為例，指令走 esp32-mp-class/led-1/command，開發板回報走 esp32-mp-class/led-1/state，其他 MQTT 工具也可以訂閱或發布這兩個 Topic。

使用自己的 MQTT 伺服器：打開語音控制頁的「進階」，填入伺服器位址、WSS 連接埠、路徑、帳號和密碼；程式裡的 BROKER、MQTT_PORT、MQTT_USER、MQTT_PASSWORD 也要改成同一台。語音控制頁不會儲存密碼，重新整理後要再輸入一次。開發板預設走不加密的 1883 連接埠，帳號密碼可能被同網路的人看到，請使用這台伺服器專用的密碼。

Telegram 機器人

  1. 在 Telegram 搜尋 @BotFather，傳 /newbot，依指示取名後會拿到 Bot Token。
  2. 範例選「Telegram 機器人控制 LED」，填入 Wi-Fi 名稱、密碼和 BOT_TOKEN，按「上傳並執行」。
  3. 傳任一則訊息給你的機器人，監控窗會顯示 CHAT_ID。把號碼填進程式，再上傳一次。
  4. 傳 /on、/off 或 /status 控制 LED；按下按鈕時，手機會收到通知。

板子約每 2 秒查一次新訊息，反應會有幾秒延遲。只有 CHAT_ID 指定的聊天室能控制板子，開機前累積的舊指令不會執行。校園網路封鎖 Telegram 時，板子會連不上，可以改用手機熱點。

Wi-Fi 只支援 2.4GHz。ESP32 連不上 5GHz 網路。

填過一次 Wi-Fi 名稱和密碼後，網站會記住最後用的那一組，之後載入其他範例時自動填入，不用再打一次。要換 Wi-Fi，直接改程式裡的 SSID 和 PASSWORD。

手機儀表板

手機儀表板可以在手機上看感測器的數值，也能用開關、按鈕和滑桿控制開發板。畫面由開發板的程式決定：程式寫了 board.gauge("溫度")，手機上就會出現溫度儀表，不用在手機上另外設定。資料經過 MQTT 伺服器，所以板子和手機不必連同一個 Wi-Fi，但都要能上網。範例 27–38 都用到手機儀表板。

使用步驟

  1. 範例選「27. 儀表板入門：開關 LED、看按鈕」，填入 Wi-Fi 名稱和密碼，按「上傳並執行」。
  2. 網站會先把儀表板工具 dash.py 存到板子的 /lib，監控窗會顯示「已把手機儀表板工具 dash.py 存到板子的 /lib」。板子上已經是同一個版本時會跳過，不會拖慢上傳。
  3. 板子連上 MQTT 伺服器後，監控窗上方會出現手機儀表板的網址和 QR code。用手機相機掃描，就會打開手機儀表板頁，主題名稱也會自動填好。
  4. 也可以自己打開手機儀表板頁（「設定與說明」裡也有連結），輸入監控窗顯示的主題名稱，再按「連線」。

元件寫法

先用 board = dash.Dashboard(TOPIC_NAME, SSID, PASSWORD) 建立儀表板，再建立元件，最後呼叫 board.start() 連線。迴圈裡每次都要呼叫 board.check()，它會收手機的操作、送出新的值，斷線時也會自動重連。

元件程式寫法手機上的樣子怎麼用
數值board.value("濕度", unit="%")大字數字加單位.set(數字或文字)
儀表board.gauge("溫度", min=0, max=50, unit="°C", color="red")半圓形儀表，顏色有 green、red、yellow、blue.set(數字)
折線圖board.chart("濕度變化", unit="%")最近 60 個值的折線，左邊標出最高、最低值和單位，下方標出手機收到的時間.set(數字)，每次是一個點
指示燈board.led("警報", color="red")亮或暗的圓燈，顏色有 green、red、yellow、blue.set(True) 亮、.set(False) 暗
文字board.text("狀態")一行文字.set("文字")
開關board.switch("LED")開關.value 是 True 或 False，板子也能用 .set() 改
按鈕board.button("響鈴")大按鈕按過時 .pressed() 回傳一次 True
滑桿board.slider("亮度", min=0, max=100)可以拖拉的滑桿，數值是整數.value 是目前的數字，板子也能用 .set() 改
提醒board.alert("門鈴")跳出提醒、發出聲音，Android 也會震動.send("有人按門鈴！")
色彩選擇board.color("燈色")色盤.value 是（紅, 綠, 藍），各 0～255
方向鍵board.pad("方向")上下左右四個鍵，按住才動、放開就停.value 是 "up"、"down"、"left"、"right"，放開時是 ""
選單board.select("模式", ["關", "亮", "閃爍"])一排選項按鈕.value 是選到的文字
文字輸入board.input("訊息")輸入框和「送出」.value 是文字，有新文字時 .changed() 回傳一次 True
數字設定board.number("濕度門檻", value=70, min=30, max=95, step=5, unit="%")數字和 − ＋ 按鈕，也能直接輸入.value 是數字，手機改了時 .changed() 回傳一次 True，板子也能用 .set() 改
紀錄表board.log("溫濕度紀錄", ["溫度", "濕度"])表格，最新的一列在最上面，可以下載 CSV.add(溫度, 濕度) 新增一列，時間由手機加上
搖桿board.joystick("搖桿")圓形搖桿，放開就回到中間.x 是左右、.y 是前後，都是 -100～100
手機傾斜board.tilt("傾斜")「開始傾斜控制」按鈕和目前的傾斜位置.x 是左右、.y 是前後，都是 -100～100；.on 表示有沒有開啟

不用擔心送太快：同一個元件最快每 0.5 秒送一次，迴圈裡一直呼叫 .set() 也不會塞爆公用伺服器，手機看到的永遠是最新的值。開關、滑桿和數字設定的值會保留在伺服器上，板子重新開機後會回到最後的狀態。一個儀表板最多 30 個元件。

方向鍵、搖桿和手機傾斜的安全設計：按住方向鍵或搖桿時，手機每 0.4 秒重送一次；手機傾斜開啟時每 0.2 秒送一次。板子超過 1 秒沒收到、或是斷線，方向鍵的 .value 會自動變回 ""，搖桿和傾斜的 .x、.y 會回到 0。手機切到別的畫面時也會自動放開。所以手機當機、沒電或離開 Wi-Fi，遙控車都會停下來。第一次測試時，先把車子架高，讓輪子懸空。

手機傾斜：手機只在 https 網址上提供傾斜感測器，所以要用正式網站，或掃描 QR code 打開的網址。iPhone 第一次按「開始傾斜控制」時會詢問能不能使用動作感測器，請選「允許」。手機平放是 0，傾斜 45 度就是最大。請直拿手機，橫拿時左右和前後會對調。電腦通常沒有傾斜感測器。

紀錄表：紀錄只存在手機頁上，手機頁打開時才收得到，最多保留最近 1000 筆（每 5 秒一筆約可記 83 分鐘）；記滿時筆數會變成紅字提醒，之後最舊的會被刪除。重新整理或關掉就會清空，記得先按「下載 CSV」。CSV 的前兩欄是手機收到的日期和時間（時間到秒），Excel 和 Google 試算表都能直接打開。要長時間記錄、手機不用一直開著時，請用 Google 試算表。

板子資訊：手機儀表板頁會在「開發板：在線」下面顯示板子的 Wi-Fi 訊號、已執行時間和剩餘記憶體，每 10 秒更新，不用寫程式。訊號 -60 dBm 以上是強，-70 dBm 以下是弱，弱的時候操作可能會延遲。剩餘記憶體一直變少時，表示程式裡可能有東西一直累積。板子的 IP 位址不會送出。

提醒的聲音：瀏覽器規定網頁要先被點過一次才能出聲音，所以手機儀表板的提醒卡片上有「開啟提醒聲音」按鈕，打開頁面後先按一下。提醒不會保留在伺服器上，手機晚一點才打開時，不會收到以前的提醒。

請 Gemini 寫儀表板程式：「Gemini 提示詞」選單的「寫手機儀表板程式」會附上全部元件的寫法，見 Gemini 提示詞。

主題名稱和 MQTT Topic：以主題名稱 dash-1 為例，所有資料都在 esp32-mp-class/dash-1/dash/ 底下：layout 是畫面上有哪些元件、state 是板子在不在線、info 是板子資訊、out/… 是板子送出的值、in/… 是手機的操作。

使用自己的 MQTT 伺服器：打開手機儀表板頁的「進階」填入伺服器設定，程式改成 dash.Dashboard(TOPIC_NAME, SSID, PASSWORD, broker="伺服器位址", port=1883, user="帳號", mqtt_password="密碼")。

關於 dash.py：不要直接修改板子上的 /lib/dash.py，下次上傳時網站會換回原本的版本。不用這個網站上傳時（例如用 Thonny），可以在板上檔案打開 /lib 下載 dash.py，再放到另一塊板子上。手機儀表板頁不需要 Web Serial，手機和電腦的瀏覽器都能開，但還沒在每一種手機上實測。

板子連不上時：學校防火牆擋 1883 連接埠時，監控窗會一直出現「連線失敗，5 秒後重試」，可以改用手機熱點。手機儀表板頁顯示「開發板：離線」或「沒有回應」時，請確認板子上的程式正在執行，而且兩邊的主題名稱一樣。

把感測器資料存到 Google 試算表

範例「DHT11 資料存到 Google 試算表」每分鐘會把日期、時間、溫度和濕度新增成一列。Google Apps Script 是免費服務，但要先設定一次。

  1. 到 Google 試算表建立新檔案，在第一列的 A1～D1 輸入標題：日期、時間、溫度、濕度。日期和時間分成兩欄，時間才會顯示到秒。
  2. 點選「擴充功能」→「Apps Script」，把原本的內容換成下面的程式後儲存： 
    function doGet(e) {
  var temp = Number(e.parameter.temp);
  var hum = Number(e.parameter.hum);
  if (isNaN(temp) || isNaN(hum)) {
    return ContentService.createTextOutput("bad data");
  }
  var book = SpreadsheetApp.getActiveSpreadsheet();
  var zone = book.getSpreadsheetTimeZone();
  var now = new Date();
  book.getSheets()[0].appendRow([
    Utilities.formatDate(now, zone, "yyyy-MM-dd"),
    Utilities.formatDate(now, zone, "HH:mm:ss"),
    temp,
    hum
  ]);
  return ContentService.createTextOutput("ok");
}
  3. 點選「部署」→「新增部署作業」，類型選「網頁應用程式」。執行身分選「我」，存取權選「所有人」，再依畫面完成授權。
  4. 複製部署後的網址，結尾是 /exec。先在瀏覽器網址列的網址後面加上 ?temp=25&hum=60 開啟，畫面顯示 ok、試算表多一列，就代表設定正確。測試完可以刪除這一列。
  5. 範例選「DHT11 資料存到 Google 試算表」，填入 Wi-Fi 名稱、密碼和 SCRIPT_URL，按「上傳並執行」。每次連到 Google 要花幾秒，所以每一列的間隔會比 SEND_SECONDS 多幾秒。

網址等於試算表的寫入權限。知道網址的人都能新增資料，不要投影或分享。不小心外洩時，請到「部署」→「管理部署作業」封存這個部署，再建立新的部署。

學校的 Google 帳號可能不允許把存取權設成「所有人」，這時請改用個人帳號。之後修改 Apps Script，要在「管理部署作業」選編輯並發布新版本，才會生效。
