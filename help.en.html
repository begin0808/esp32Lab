This site uses MicroPython: you write programs in Python, not Arduino C++. The board needs the MicroPython firmware first, and installing it erases any Arduino program on the board. Arduino programs cannot run here. If you paste one, a notice appears and you can copy a prompt asking Gemini to rewrite it. See the differences between MicroPython and Arduino.

This site is a beta and is still being developed. There are many combinations of boards and examples, and not all of them have been tested, so you may run into problems. If you find a mistake or would like a feature, please email me.

Getting started

You do not need the Arduino IDE or any development setup. Open this site in Chrome or Edge on a computer, and connect the board with a USB cable that can carry data.

  1. Install a driver: only if the computer cannot find the board. Boards whose USB goes straight to an S2, S3 or C3 chip usually need none. If the board's USB chip is a CP2102, install the CP210x driver; if it is a CH340, install the CH340 driver. "Settings and help" at the top right of the editor has these links too, along with the pinout, the voice control page, and the language, style and font settings.
  2. Connect the board: close programs that hold the serial port, such as the Arduino IDE. Then press "Connect board" and choose the serial port that appears.
  3. Install the firmware: only needed the first time, or after flashing an Arduino program. Pressing "Install firmware" erases all programs and files on the board, so do not unplug the USB cable while it runs. For boards whose USB goes straight to the chip, press RST afterwards and connect again.
  4. Get a program: choose a built-in example, or press "Copy Gemini prompt", fill in your wiring and what you want, paste it into Gemini, and paste the MicroPython program it writes back into the editor.
  5. Upload and run: press "Upload and run". The program is saved as main.py on the board and runs automatically whenever the board powers up. The first line in the serial monitor shows the program's size and how many seconds the upload took, followed by the program's output and errors.

The differences between MicroPython and Arduino

Both can control an ESP32, and neither is better in every way. This site uses MicroPython because there is nothing to install, changes run within seconds, and error messages are easier to understand, which suits classrooms and quick experiments.

MicroPython (this site)Arduino C++
LanguagePython, short and easy to start withC++, with declared types and stricter syntax
SetupWorks in a browser after one firmware installNeeds the Arduino IDE and board package, reinstalled if the computer is restored
Uploading changesNo compiling, usually done in secondsCompiles and flashes every time, so it takes longer
Finding errorsErrors give the line number, and you can try commands in the monitorThe compiler catches syntax errors first; runtime problems are mostly traced through serial output
SpeedSlower, but usually enough for sensing and controlMuch faster, suits heavy computing and high-speed work
MemoryThe interpreter takes up space, so less is leftMore is available, better for large programs
TimingGarbage collection can cause short pauses, so it does not suit precise timingMore precise timing
LibrariesCommon features are built in, others may need code you find yourselfPlenty available, for most modules
Best forTeaching beginners, writing code with AI, sensor and IoT experimentsCamera images, high-speed signals, large or long-running projects

One board can switch back and forth, but it runs only one at a time. Flashing from the Arduino IDE overwrites MicroPython and the files on the board. To come back, press "Install firmware" on this site.

Talking to the board with the REPL

REPL stands for Read-Eval-Print Loop: it reads a command, runs it, prints the result, and repeats. With main.py you write a whole program and then upload it. The REPL works one line at a time, which suits checking wiring, trying commands and finding mistakes.

Commands you type here run on the board straight away, but are not saved to main.py. Variables and the effects of commands are gone after a restart or an upload.

Getting started

  1. Press "Connect board". Connecting stops any running program, and the monitor shows the >>> prompt.
  2. If a program is running (for example, just after "Upload and run"), press "Stop" first.
  3. Type a command in the box below the monitor and press Enter.

Try it

Type these commands in order. The second group uses GPIO 2, the onboard LED of common ESP32 boards. For other chips or boards, use your own pin.

1 + 1

from machine import Pin
led = Pin(2, Pin.OUT)
led.value(1)
led.value(0)

import os
os.listdir()

Typing several lines

Type for i in range(3): and press Enter, and the box starts an indented new line. After the body, press Enter twice more (a blank line, then send) to run the whole block. You can also paste several lines and press "Send". The monitor shows ===, which is the board's normal prompt while it receives several lines.

for i in range(3):
    print(i)

Put longer programs in the editor on the left and use "Upload and run", so they are saved.

The REPL really controls the hardware. As in a program, wrong pin settings can still affect connected parts, so do not type file-deleting commands you do not understand. Earlier commands stay only in this tab's memory. They are cleared when you reload or change the language, and are never saved in the browser.

Watching sensor values on a chart

The top right of the monitor switches between "Text" and "Chart". On "Chart", the numbers your program prints are drawn as a line chart, which is good for watching a temperature change, a knob turn or a distance. Data keeps being recorded whichever view is shown, so nothing is missed when you switch back.

How to print values that can be charted

The program printsThe chart shows
print("temp:", t)One line called "temp"
print("Temperature:", t, "°C Humidity:", h, "%")Two lines, "Temperature" and "Humidity". Units after a number are ignored
print(t, h)When only numbers are printed, they are called "value1", "value2" in order
  • The name is the one word before the colon (or equals sign), with no spaces. For example room_temp: works, but room temp: only takes temp.
  • Lines without numbers, error messages, >>> command lines and the chip's own messages after a restart are not drawn. Up to 8 lines can be drawn.
  • Examples 4 "Potentiometer LED dimmer", 7 "Automatic night light (photoresistor)", 9 "Ultrasonic distance (HC-SR04)", 10 "DHT11 temperature and humidity (monitor)" and 11 "DS18B20 thermometer" can be charted without any changes. Their opening comments also suggest what to try, such as turning the knob, covering the photoresistor or breathing on the DHT11.

Try it

You can try this without any parts. Upload the program below and switch to "Chart" to see two waves.

import math, time

i = 0
while True:
    print("sin:", math.sin(i / 50), "cos:", math.cos(i / 50))
    i += 1
    time.sleep(0.05)

Exporting CSV

"Export CSV" downloads esp32-data-date-time.csv. The first column is the time in seconds since the first value, followed by one column per line. A value not printed on a row is left empty. Excel and Google Sheets open it with Chinese names intact, so you can make charts, take averages or write a lab report.

The site keeps up to the latest 100,000 rows. Beyond that the oldest are dropped, and a note appears above the chart. Data lives only in this tab and is cleared when the page is reloaded, so export long recordings. To keep data for longer, see Saving sensor data to Google Sheets.

Can I use an Arduino UNO?

No. This site only has MicroPython firmware for the ESP32 family, and the classic UNO R3 has too little memory to run MicroPython. ESP32 Lab also has an Arduino edition, but "Arduino" there means the Arduino framework you write code with (setup(), digitalWrite() and so on), not the Arduino board, so it does not support the UNO either.

Tips for asking Gemini

  • State the model and pins: for example, "MAX7219 8×8 LED matrix, DIN on GPIO 23, CLK on GPIO 18, CS on GPIO 5".
  • Use a single file: this site uploads only main.py. An ImportError means the program uses a module the firmware lacks, so ask Gemini to "put this part's driver in the same main.py as the main program".
  • Name the language: ask for MicroPython v1.29.0, not Arduino C++. The site's "Copy Gemini prompt" already includes these requirements.

Wiring notes

The pin table below is for the ESP32 (including ESP32-S and ESP-WROOM-32 modules). For other chips, see the table at the end of this section.

Unplug the USB cable before wiring or changing wires. A wrong voltage or a short circuit can destroy the board.

  • GPIO pins only accept 3.3V: do not connect 5V signals straight to a GPIO.
  • Do not drive high-current parts directly: motors, long LED strips and the like need an external supply or driver module. With an external supply, connect its GND to the ESP32's.
  • Check the pin numbers: numbers in programs are GPIO numbers, so compare them with the markings on the board or the pinout.
PinsAdviceWhy
GPIO 6–11Do not useConnected to the internal flash, so wiring them can stop the board working. GPIO 9 and 10, marked RX1 and TX1 on the pinout, are included.
GPIO 34, 35, 36, 39Input onlyThey cannot output, and have no internal pull-up or pull-down.
GPIO 25–27, GPIO 0, 2, 4, 12–15No analog with Wi-FiThese are ADC2 pins, which cannot read analog values while Wi-Fi is on. Use GPIO 32–39 for analog input.
GPIO 0, 2, 5, 12, 15Use with careTheir levels at power-up affect booting. If GPIO 12 is high at power-up, the board may not start.
GPIO 1, 3AvoidUsed by the USB serial port, so other parts here interfere with uploading and the monitor.
GPIO 4, 13, 16–19, 21–23, 25–27, 32, 33Good first choiceLeast likely to conflict for general digital input and output (GPIO 21 and 22 are often used for I2C).

Voice control steps

  1. Choose the example "Voice-controlled LED (MQTT)", fill in your Wi-Fi name and password, and press "Upload and run".
  2. When the monitor shows "Connected to the MQTT broker", note the MQTT topic name.
  3. Open the voice control page, enter the topic name and press "Connect".
  4. Press the voice button, allow the microphone, and say "on", "off" or "blink". A sentence such as "turn the light on" also works.

If voice does not work, press the On and Off buttons, or use your phone keyboard's microphone in the text command box. On Windows you can also press Win + H for voice typing.

Topic names and MQTT topics: the name you enter makes up two topics. With led-1, commands use esp32-mp-class/led-1/command and board reports use esp32-mp-class/led-1/state. Other MQTT tools can subscribe or publish to them too.

Using your own MQTT broker: open "Advanced" on the voice control page and fill in the broker address, WSS port, path, username and password. Change BROKER, MQTT_PORT, MQTT_USER and MQTT_PASSWORD in the program to the same broker. The voice control page does not save the password, so enter it again after reloading. The board uses unencrypted port 1883 by default, so others on the network may see the login. Use a password made only for this broker.

Telegram bot

  1. Search for @BotFather on Telegram, send /newbot, and follow the steps to name your bot. You will get a bot token.
  2. Choose the example "Telegram bot LED", fill in your Wi-Fi name, password and BOT_TOKEN, and press "Upload and run".
  3. Send your bot any message, and the monitor shows your CHAT_ID. Put the number in the program and upload again.
  4. Send /on, /off or /status to control the LED. Pressing the button sends a notification to your phone.

The board checks for new messages about every 2 seconds, so replies can take a few seconds. Only the chat set in CHAT_ID can control the board, and old commands from before it started are not run. If your school network blocks Telegram, try a phone hotspot.

Wi-Fi is 2.4GHz only. The ESP32 cannot connect to 5GHz networks.

Saving sensor data to Google Sheets

The example "Log DHT11 data to Google Sheets" adds a row of time, temperature and humidity every minute. Google Apps Script is free, but needs setting up once. This example has been tested with simulated hardware and simulated Google responses, but not with a real Google Sheet.

  1. Create a new Google Sheet, and enter the headings in the first row: Time, Temperature, Humidity.
  2. Choose "Extensions" → "Apps Script", replace the contents with the program below, and save: 
    function doGet(e) {
  var temp = Number(e.parameter.temp);
  var hum = Number(e.parameter.hum);
  if (isNaN(temp) || isNaN(hum)) {
    return ContentService.createTextOutput("bad data");
  }
  var sheet = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  sheet.appendRow([new Date(), temp, hum]);
  return ContentService.createTextOutput("ok");
}
  3. Choose "Deploy" → "New deployment", with the type "Web app". Set "Execute as" to "Me" and "Who has access" to "Anyone", then complete the authorization.
  4. Copy the deployment URL, which ends in /exec. First test it in a browser by adding ?temp=25&hum=60 to the end. If the page shows ok and the sheet gains a row, the setup is correct. You can delete that row afterwards.
  5. Choose the example "Log DHT11 data to Google Sheets", fill in your Wi-Fi name, password and SCRIPT_URL, and press "Upload and run".

Anyone with the URL can write to the sheet. Do not project or share it. If it leaks, archive the deployment under "Deploy" → "Manage deployments" and create a new one.

School Google accounts may not allow access for "Anyone". If so, use a personal account. After changing the Apps Script later, edit the deployment in "Manage deployments" and publish a new version for the change to take effect.

Privacy and safety

  • Code: the site does not upload your code to a server. It exists only in this browser and on your board. GitHub only serves the site's files and may log connection details such as IP addresses, but never receives your code.
  • Visit statistics: the site uses GoatCounter to count page views, and the footer shows the editor page's total. Each page load sends only the page path, the page title and the referring site. GoatCounter also receives the IP address and browser details that every request carries, and uses them to estimate unique visitors. No cookies are used, and no code, Wi-Fi passwords, serial output or MQTT topic names are sent.
  • Wi-Fi passwords: the password is part of the program, so it is stored as plain text in the browser and in main.py on the board. Delete it before using a shared computer or lending out a board; see "Shared computers and boards" below.
  • Before pasting into Gemini: "Copy for Gemini" and the "convert to MicroPython" prompt hide common forms of Wi-Fi details, logins, tokens and Apps Script URLs, but may not catch them all. Copying the program yourself hides nothing, so delete passwords first.
  • Screenshots and projectors: the editor shows your password, so cover it before projecting or sharing your screen. A dedicated class Wi-Fi or phone hotspot is recommended.
  • Voice control: commands pass through a public MQTT broker with no encryption or access control, and anyone who knows the topic name can send them. It only suits low-risk experiments such as LEDs. Do not control sockets or door locks, and keep personal details out of the topic name.
  • Speech recognition: your browser and its speech service handle recognition, which usually needs the internet.
  • Telegram bot token: the token is the bot's password, and anyone with it can impersonate your bot, so do not project or share it. If it leaks, send /revoke to @BotFather for a new one. The example does not verify the server certificate, so do not control anything important.

Shared computers and boards

Closing the page does not clear your code. The code and any Wi-Fi password in it stay in the browser, and the next person using the same computer and browser account will see them when they open the site.

Before leaving a computer or returning a board:

  1. To keep your program: first delete the Wi-Fi name and password, MQTT login, bot token and Apps Script URL from it, then press "Download main.py". The downloaded file does not hide these automatically.
  2. To clear the browser: delete everything in the editor. The editor saves automatically, so this replaces the old contents too.
  3. To clear the board: upload a program with no passwords, which overwrites main.py. To erase every file on the board, reinstall the firmware.

Restore cards in computer labs usually clear browser data on restart, but the next user can still see it until then. Restore cards do not affect the board, so its data stays until you remove it.

Common questions

Installing the firmware shows "Serial data stream stopped"

This usually happens before erasing starts, so the board is not damaged and keeps running its old program. Reload the page, unplug and replug the USB cable, connect again and retry; a CH340 board in testing was installed this way. If it still fails, plug into a USB port on the computer itself, try another USB cable, or hold IO0, press EN once, release IO0, and then install.

I chose the wrong chip. Will uploading damage the board?

The wrong menu choice does not affect the firmware, because the site detects the chip itself during installation. Uploaded programs do not change the firmware either, but the pins may be wrong. With an ESP32 set to S2, S3 or C3, examples may use GPIO 6–11, and the board may crash or keep restarting. Choose the right chip and example, then upload again; if you cannot upload, hold IO0 and reinstall the firmware. What can really damage a board is wiring, such as 5V on a GPIO, a shorted supply, or an output pin connected straight to power or GND.

Can I take pictures with an ESP32-CAM?

Not at the moment. The official MicroPython firmware has no camera module. Taking pictures needs a third-party build, which this site does not include.

An ESP32-S2, S3 or C3 will not connect during firmware installation, or does nothing afterwards

On boards whose USB goes straight to the chip, the serial port disappears briefly when the chip restarts. If it will not connect, hold BOOT, press RST once, release BOOT, then press "Connect board" and install. Afterwards, press RST and wait 2 seconds before connecting. If the board has two USB ports, try the one marked UART or COM.

No serial port is listed after pressing "Connect board"

First try a USB cable you know carries data, because some only charge. Then check that the right driver is installed, and replug the board.

Connection fails, or the serial port is in use

Close the Arduino IDE and any other tab of this site. Only one program can use the serial port at a time.

It says "MicroPython was not found"

This is normal on first use or after flashing an Arduino program. Press "Install firmware". There is nothing else to download.

Firmware installation keeps failing to connect

The site reconnects on its own, up to 10 tries, and writes each try in the monitor. If all 10 fail, hold the IO0 (BOOT) button on the board and press "Install firmware" again. You can let go once writing starts. Some boards have an unreliable auto-reset circuit, and holding IO0 is the most reliable fix. When reporting a problem, please include the lines under "Connection log" in the monitor.

It says "This board is an ESP32-xx. Only ESP32, ESP32-S2, S3 and C3 are supported"

This board's chip is not supported, so the included firmware cannot be used. Please use a board with one of those four chips.

The monitor shows a red "The program hit an error"

Press "Copy for Gemini", paste the error and code into Gemini to fix it, then paste the new program back and upload it.

It says Wi-Fi connection failed

Check that the name and password are exactly right, including capitals, and that the network is 2.4GHz.

My phone cannot open the 192.168.x.x page

Check that the phone and board are on the same Wi-Fi, and try turning off the phone's mobile data. School networks may block devices from reaching each other, so try a phone hotspot or the voice control page (MQTT).

No microphone permission appears, and voice does not work

Check that you opened the HTTPS voice control page, not http://192.168.x.x. If you refused before, allow it in the browser's site settings.

The voice control page says "no response" or "offline"

Check that the board's program is running, that the monitor shows it connected to the MQTT broker, and that the topic names on the page and in the program match exactly. School networks may block port 1883, so try a phone hotspot.

The voice control page says the MQTT username or password is wrong

Check that the login matches the broker's settings, and that this account may use topics starting with esp32-mp-class/. The password is not saved, so enter it again after reloading.

The Google Sheets example says "Google did not return ok"

Usually access was not set to "Anyone" when deploying, or a school account does not allow it. Test the URL in a private browser window, where it should show ok. If no data is added, also check that the URL ends in /exec.

After pressing "Stop", will the program run again by itself?

Yes. "Stop" only interrupts the current run. main.py stays on the board, and runs again at the next power-up or restart.
