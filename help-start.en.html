Getting started

You do not need the Arduino IDE or any development setup. Open this site in Chrome or Edge on a computer, and connect the board with a USB cable that can carry data.

  1. Install a driver: only if the computer cannot find the board. Boards whose USB goes straight to an S2, S3 or C3 chip usually need none. If the board's USB chip is a CP2102, install the CP210x driver; if it is a CH340, install the CH340 driver. "Settings and help" at the top right of the editor has these links too, along with the pinout, the voice control page, the phone dashboard page, and the language, style and font settings.
  2. Connect the board: close programs that hold the serial port, such as the Arduino IDE. Then press "Connect board" and choose the serial port that appears.
  3. Install the firmware: only needed the first time, or after flashing an Arduino program. Pressing "Install firmware" erases all programs and files on the board, so do not unplug the USB cable while it runs. For boards whose USB goes straight to the chip, press RST afterwards and connect again.
  4. Get a program: choose a built-in example, or press "Gemini prompts" → "Write a new program", fill in your wiring and what you want, paste it into Gemini, and paste the MicroPython program it writes back into the editor.
  5. Upload and run: press "Upload and run". The program is saved as main.py on the board and runs automatically whenever the board powers up. The first line in the serial monitor shows the program's size and how many seconds the upload took, followed by the program's output and errors.
  6. Just trying something: press "Run (no save)" or F5. The program runs straight from the board's memory and is not saved as main.py; see Run (no save).

Run (no save) and Upload and run

"Run (no save)" stops the current program, clears the variables left from last time, and sends the code in the editor to the board's memory to run at once. It is not saved as main.py. While a board is connected you can also press F5; without a board, F5 still reloads the page.

Run (no save)Upload and run
SpeedFaster: no file to write and no restartA little slower
After a restart or power cycleThe program is gone and the board runs its own main.py againThe program stays on the board and runs at every power-up
Best forTrying things, changing values, finding mistakesFinished projects, or running away from the computer

A broken program is nothing to worry about: press "Restart" or unplug the power, and the board runs its own main.py again. Once the program works, press "Upload and run" to keep it on the board. The same goes for a program that restarts the board, for example with deep sleep or machine.reset(): it wakes into its own main.py, and the monitor says so.

Looking at variables after the program ends

After the program ends, or after you press "Stop", its variables are still on the board. Type a variable's name in the REPL below the serial monitor to see its last value. For example:

total = 0
for i in range(1, 11):
    total = total + i

When it has run, typing total in the REPL shows 55, and i shows 10. When hunting for a mistake, this is easier than adding print everywhere. "Upload and run" restarts the board, so this works only with "Run (no save)".

In error messages, File "<stdin>", line 3 means line 3 in the editor, the same line numbers as main.py. "Copy for Gemini" works as usual.

If a Chromebook has only USB-C ports, a USB-C to USB-A adapter with the board's usual USB cable works, or you can use a USB-C to Micro USB data cable. On a school-managed Chromebook, if no serial port appears after pressing "Connect board", the management policy may have turned the feature off; ask the school's IT staff to allow it in the Google Admin console.

The differences between MicroPython and Arduino

Both can control an ESP32, and neither is better in every way. This site uses MicroPython because there is nothing to install, changes run within seconds, and error messages are easier to understand, which suits classrooms and quick experiments.

MicroPython (this site)Arduino C++
LanguagePython, short and easy to start withC++, with declared types and stricter syntax
SetupWorks in a browser after one firmware installNeeds the Arduino IDE and board package, reinstalled if the computer is restored
Uploading changesNo compiling, usually done in secondsCompiles and flashes every time, so it takes longer
Finding errorsErrors give the line number, and you can try commands in the monitorThe compiler catches syntax errors first; runtime problems are mostly traced through serial output
SpeedSlower, but usually enough for sensing and controlMuch faster, suits heavy computing and high-speed work
MemoryThe interpreter takes up space, so less is leftMore is available, better for large programs
TimingGarbage collection can cause short pauses, so it does not suit precise timingMore precise timing
LibrariesCommon features are built in, others may need code you find yourselfPlenty available, for most modules
Best forTeaching beginners, writing code with AI, sensor and IoT experimentsCamera images, high-speed signals, large or long-running projects

One board can switch back and forth, but it runs only one at a time. Flashing from the Arduino IDE overwrites MicroPython and the files on the board. To come back, press "Install firmware" on this site.
